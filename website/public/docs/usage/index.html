Using AgentOS

Everything here works from the desktop app too. The CLI is shown because it is shorter to write down.

Workspaces and sessions

$ agenthost status    # sandbox health, agents, login state
$ agenthost workspace add ~/code/myproject --profile packages
$ agenthost run ~/code/myproject claude "Summarise this repo"
$ agenthost chat ~/code/myproject codex    # interactive
$ agenthost run ~/code/myproject claude "What's wrong here?" --attach crash.log
$ agenthost voice download    # local speech model for voice input (once)

A workspace's --profile decides what its sessions may reach on the network besides the agent's own provider:

ProfileAllows
agent-onlyNothing besides the agent's provider
packagesPackage registries
githubGitHub
webAny public site (local and private addresses stay refused)

Combine them with commas, for example --profile packages,github. When a session is refused a host, the CLI prints the command that allows it.

Quick tasks

The built-in Quick tasks workspace needs no project: each session gets a fresh, empty folder of its own, with open web so the agent can look things up.

$ agenthost run quick claude "What changed in the latest Rust release?"

Switch open web off on the desktop's Workspaces screen, or with agenthost workspace set quick --profile agent-only.

New projects from the phone

The phone can turn a folder inside your project folders (by default ~/Code) into a workspace, or create a new one there. Only the computer chooses which folders those are:

$ agenthost project roots --set ~/Code,~/Work
$ agenthost project ls

Several logins for one agent

Have a work and a personal subscription for the same agent? Give each its own config folder and add it as a profile. New sessions can then pick it, on the desktop and the phone from the agent list, or here as agent:name:

$ agenthost agent add claude work --config-dir ~/.claude-work
$ agenthost agent list    # shows the login command if needed
$ agenthost run ~/code/myproject claude:work "Summarise this repo"

A profile's folder is writable only to sessions that use it and hidden from every other session. Profiles work for Claude Code, Codex and OpenCode, and for Cursor on Linux; not yet for Antigravity.

Automations

An automation is a saved session that starts by itself: on a schedule, when a webhook arrives, or when you press Run Now. Each run is an ordinary session, so its transcript is the run's output.

$ agenthost automation add "Upgrade dependencies" -w ~/code/myproject -a claude \
    --cron "0 3 * * 1" --auto-approve create_pull_request,git_push \
    --prompt "Upgrade dependencies, run the tests, open a pull request."
$ agenthost automation ls    # next run, last result
$ agenthost automation run <id> --wait    # now, and print the summary
$ agenthost automation runs <id>    # history; each run names its session
  • Schedules are cron in the computer's own time, at most every 5 minutes.
  • The host only runs while the computer is awake. A time missed by up to 12 hours runs once when it is back; an older one is recorded as skipped.
  • A run still going after its time limit (60 minutes by default) is stopped.
  • An automation may let its runs open pull requests and push their own branch without asking. Anything else asks as usual, and your phone gets 12 hours to answer.

Webhooks

Webhook automations are set up on the desktop and need a relay. Each gets a URL on your relay; the relay seals each request to the host as it arrives, and the host checks the sender's signature before starting a run.

For Sentry:

  1. Connect the Sentry MCP connector (Settings → Connectors) and switch it on for the workspace, so runs can read the issue.
  2. Create the automation and copy its webhook URL: 
    $ agenthost automation add "Investigate Sentry alerts" -w ~/code/myproject -a claude --webhook sentry --secret <client secret>
  3. In Sentry, create an internal integration (Settings → Developer Settings → Custom Integrations), paste the URL as its Webhook URL, turn on Alert Rule Action, and copy its Client Secret into the automation.
  4. In the alert rules you want investigated, add the action "Send a notification via" your integration.

GitHub webhooks (--webhook github) and any other sender (--webhook generic) work the same way. The payload is attached to the run as webhook.json, and fields can go in the prompt as {{payload.some.field}}. Alert text is passed to the agent as untrusted data, never as instructions.

Debugging

$ AGENTHOST_ACP_TRACE=1 agenthostd run    # log raw ACP traffic per session

The installed host logs to <data folder>/logs/host.log. The full reference is in docs/usage.md.
